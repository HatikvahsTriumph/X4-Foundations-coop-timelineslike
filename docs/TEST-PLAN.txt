# Test plan — 0.1.1

Copy this into a text file, run the sections in order, and keep the log files. Report anything
unexpected with:
**T-number + what you saw + the key host log lines + the key client log lines + reproducible? y/n**

Log files: `Documents\Egosoft\X4\<profile>\x4native\x4mp_native\x4mp_native.log`

---

## T0 — Baseline self-check (no multiplayer needed)

- [ ] the shipped DLL is `567,296 B` and reports build id `run26x-npcveto`
- [ ] the pack's `extensions\` contains no `x4mp_native_live_*.dll` or `*.bak` leftovers
- [ ] level MD = **26 cues**, test world MD = **15 cues** (31 means the probes were not removed)

## T1 — World and handshake

- [ ] both players use the **same** New Game entry
- [ ] host log: `local world fingerprint sig=xxxxxxxx sectors=3` equals the peer's line
- [ ] if they differ: the window title shows `[X4MP WORLD MISMATCH]` (go back to the main menu)
- [ ] kill the host: the client **freezes** instead of drifting away

## T2 — Client ship (this release's focus #1)

- [ ] the client's ship is the Terran **Osaka**, named `X4MP LVL Client Osaka`
- [ ] the string `X4MP LVL Client Behemoth` never appears in the client log
- [ ] the host can see the ghost replica (`T1 ghost replica uid=0 -> NNNN`) and it follows

## T3 — Probes are gone (focus #2)

- [ ] between 22 s and 70 s after world start there are **no** muzzle flashes or explosions
- [ ] the log never contains `X4MP FX probe`
- [ ] the log never contains `X4MP_P2Fx`

## T4 — NPC death case (focus #3)

- [ ] the host brings any NPC to 0 hull
- [ ] the client's copy disappears with the host's, and the client log has **no**
      `puppet id=NN is a hull-0.0 remnant - not mapped`
- [ ] the host log shows `NPC veto applied lid=...` (rate-limited to 5 s)
- [ ] counter-example to report: "no NPC visible on the client" / `client sync mapped=0`

## T5 — Second ghost death (QA P1-8 semantics)

- [ ] let the peer's ship be destroyed twice in one session
- [ ] the ghost explodes and is rebuilt **both** times (if only the first one works, report it:
      P1-8 needs `reset_cue` instead of `instantiate`)

## T6 — 0.1 regression basics

- [ ] NPC pose follows the host (~10 Hz); the client does not broadcast its own NPCs
- [ ] damage authority: the client hits a host-side NPC ⇒ client log
      `client attack -> host`, host log `PEER DAMAGE applied` (and it only ever goes down)
- [ ] station lane: `station lane rows(sent/recv/applied)` counts grow
- [ ] mission flow: waves 1-3, the carrier, station 2 destroyed ⇒ win/lose is announced

## T7 — Review merge (2026-10-13) — the two things this build is about

Run these after T6. They are the reason this build exists; everything else is a regression check.

Handy one-liner for any log below (the profile folder is the numeric one under
`Documents\Egosoft\X4\`):

```powershell
$log = "$env:USERPROFILE\Documents\Egosoft\X4\<profile>\x4native\x4mp_native\x4mp_native.log"
Select-String -Path $log -Pattern 'X4MP STN|module=|station lane|WRITE LOST|NPC veto|non-numeric|handler .* failed|Property lookup' | Select-Object -Last 60
```

### T7.1 — station module index (pins down P0-2 / P0-3)

- [ ] new game, wait until both stations and their modules exist (host + client both in the world)
- [ ] on the host, hit **one single, known module** of station 1 and note which one you hit
- [ ] the host log then has a `module=` line naming `X4MP STN N#K`, and the hull that changes on the
      client must be **that same module** (this is the whole point of the fix)
- [ ] the client log must not show the old `PEER DAMAGE VERIFY ... -> WRITE LOST` burst
- [ ] report: the DLL `module=` line + which module visibly lost hull

### T7.2 — a dead station must not shift the rest (P0-3)

- [ ] destroy **station 1 completely** on the host, then keep fighting
- [ ] station 2's modules still sync: `station lane rows(sent/recv/applied)` keeps growing and the
      client keeps showing applied rows (not a flat "sent only" line)
- [ ] destroy station 2 as well and confirm the mission win still fires

### T7.3 — level globals / freeze rate (P1-5, P1-6)

- [ ] from a new game onward the log has no `Property lookup failed` next to destroy events
- [ ] kill the host (close the game): the client freezes, and the freeze cue in the client log ticks
      half as often as the old build (200 ms instead of 100 ms)

### T7.4 — peer death, twice (P1-8)

- [ ] let the peer's ship be destroyed **twice** in one session
- [ ] the ghost is removed and rebuilt both times. Removal stays silent (`explosion="false"`): the
      replica disappears, no explosion — that is intended, not a bug

### T7.5 — installer / tool hardening (P1, P2)

- [ ] `1-INSTALL.bat`: at the host-IP prompt type `999.999.999.999` ⇒ rejected; type `q` ⇒ clean exit
      (before: the loose regex accepted 999.x, and an empty line spun forever)
- [ ] `tools\x4mp_savecheck.ps1` against your biggest save ⇒ finishes in seconds
      (before: it copied the rest of the save file once per `<hull>` record)
- [ ] a normal session produces no `x4mp_bridge: non-numeric field` lines. If one appears, that
      payload really was malformed — report the line (it used to fail silently instead)
- [ ] no `x4mp_bridge: handler ... failed` lines: one broken lane now logs and the other 21 keep running

## Known issues you should still expect

* **being verified by this build:** station module rows used to land on the wrong module (name/table
  base mismatch, then index drift once a station died). T7.1/T7.2 are the acceptance test for that
  fix. If `applied` still lags far behind `sent`, capture the T7.1 pair of lines before reporting.
* a turret destroyed on the host may keep firing on the client (the turret lane is not implemented yet);
* the client cannot see the other player's weapon fire (the effect line is deliberately not in
  this package);
* `NPC veto applied` lines are rate-limited, so a burst of corrections only prints a few lines.
* uninstalling removes the third-party `x4native` extension as well (known, deliberate).
